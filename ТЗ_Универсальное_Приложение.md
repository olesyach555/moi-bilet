## 1. ОБЩИЕ СВЕДЕНИЯ

### 1.1 Назначение
Разработка универсального шаблонного приложения, который может быть быстро адаптирован под любую из 30 предложенных бизнес-задач (Адвокатская деятельность, Заповедники, Банки, ВУЗы и т.д.). Приложение должно иметь гибкую архитектуру с модульной структурой для минимизации переработок при смене предметной области.

### 1.2 Основные требования
- ✓ Полностью русский интерфейс (меню, кнопки, сообщения об ошибках, справка)
- ✓ Полностью русские названия таблиц, полей, хранимых процедур в БД
- ✓ Архитектура слоев (Presentation → Business Logic → Data Access)
- ✓ Пустая (не заполненная) БД с базовой структурой для быстрого расширения
- ✓ Соответствие стандартам кодирования (CamelCase, осмысленные имена, комментарии)
- ✓ Без использования значений по умолчанию (Form1, button3 и т.д.)
- ✓ Готовность к печати и экспорту данных

## 2. ФУНКЦИОНАЛЬНЫЕ ТРЕБОВАНИЯ

### 2.1 Основной функционал
Приложение должно обеспечивать следующие операции:

#### 2.1.1 Управление данными (CRUD)
- **Создание** (Create): Добавление новых записей в основную таблицу
- **Чтение** (Read): Загрузка и отображение данных в DataGridView
- **Обновление** (Update): Изменение существующих записей
- **Удаление** (Delete): Удаление записей с подтверждением

#### 2.1.2 Поиск и фильтрация
- Поле для поиска по главному идентификатору или названию
- Кнопка "Найти" с подсветкой результатов
- Фильтрация по статусу (активный/архивный)

#### 2.1.3 Печать и экспорт
- Кнопка "Печать" для вывода таблицы на печать
- Экспорт в формат, соответствующий предметной области

#### 2.1.4 Уведомления и обработка ошибок
- Сообщение об успешном добавлении/изменении/удалении записи
- Обработка ошибок БД (ключи, ограничения)
- Валидация введённых данных перед сохранением
- Подтверждение удаления записи

### 2.2 Нефункциональные требования
- **Производительность**: Загрузка 1000 записей < 2 секунды
- **Надежность**: Восстановление после потери соединения с БД
- **Безопасность**: Использование параметризованных запросов против SQL-injection
- **Масштабируемость**: Возможность добавления новых полей/таблиц без переработки ядра

## 3. ТРЕБОВАНИЯ К БАЗЕ ДАННЫХ

### 3.1 Общая структура
```
БД: [НазваниеПриложения]
  ├── Таблица: dbo.Основные_Объекты
  │   ├── ID (PK, int, IDENTITY)
  │   ├── Наименование (nvarchar(255), NOT NULL, UNIQUE)
  │   ├── Описание (nvarchar(MAX), NULL)
  │   ├── Статус (nvarchar(50), DEFAULT='Активно')
  │   ├── Дата_Создания (datetime, DEFAULT=GETDATE())
  │   └── Дата_Изменения (datetime, DEFAULT=GETDATE())
  │
  ├── Таблица: dbo.Справочник_Статусы
  │   ├── ID (PK, int)
  │   └── Наименование (nvarchar(100), UNIQUE)
  │
  └── Хранимые процедуры:
      ├── sp_Получить_Все_Объекты
      ├── sp_Получить_Объект_По_ID
      ├── sp_Вставить_Объект
      ├── sp_Обновить_Объект
      ├── sp_Удалить_Объект
      └── sp_Поиск_Объектов
```

### 3.2 Правила создания таблиц
- Все таблицы в схеме **dbo**
- Первичный ключ: **ID** (int, IDENTITY, PRIMARY KEY)
- Обязательное поле: **Наименование** (уникальное)
- Поля дат: **Дата_Создания**, **Дата_Изменения** (datetime, автоматическое заполнение)
- Поле статуса: **Статус** (nvarchar, со справочником)
- Все VARCHAR → **NVARCHAR** (поддержка кириллицы)
- Ограничения: CHECK, UNIQUE, FOREIGN KEY в зависимости от логики

### 3.3 Пример структуры для "Адвокатской деятельности" (для вставки позже)
```sql
-- Основная таблица расширяется:
ALTER TABLE dbo.Основные_Объекты ADD
    Телефон nvarchar(20),
    Email nvarchar(100),
    Специализация nvarchar(255),
    Лицензия nvarchar(100);
```

## 4. ТРЕБОВАНИЯ К АРХИТЕКТУРЕ

### 4.1 Слои приложения

#### Слой Presentation (GUI)
- **Главная форма**: `ГлавнаяФорма` (MainForm.cs)
  - Меню приложения (Файл, Правка, Справка)
  - Таблица данных (DataGridView)
  - Панель инструментов (кнопки Добавить, Изменить, Удалить, Поиск, Печать)
  - Строка состояния (количество записей)

- **Форма добавления/редактирования**: `ФормаОбъекта` (ObjectForm.cs)
  - Поля ввода для основных атрибутов
  - Кнопки "Сохранить", "Отмена"
  - Валидация данных перед отправкой

- **Форма поиска**: `ФормаПоиска` (SearchForm.cs)
  - Поле поиска
  - Выпадающий список для фильтра
  - Кнопка "Найти"

#### Слой Business Logic (BLL)
- **Класс**: `МенеджерОбъектов` (ObjectManager.cs)
  - Методы валидации
  - Бизнес-правила (если есть)
  - Преобразование данных

#### Слой Data Access (DAL)
- **Класс**: `ДоступКДанным` (DataAccess.cs)
  - Методы подключения к БД
  - Выполнение CRUD операций через хранимые процедуры
  - Обработка исключений БД
  - Логирование ошибок

- **Конфиг**: `AppSettings.cs` или App.config
  - Строка подключения
  - Параметры логирования

### 4.2 Именование классов и методов
```csharp

public bool ПроверитьДанные() { }
```

## 6. ТРЕБОВАНИЯ К ОБРАБОТКЕ ОШИБОК

### 6.1 Типы ошибок и обработка
| Ошибка | Сообщение | Действие |
|--------|-----------|----------|
| Отсутствие соединения с БД | "Ошибка подключения к БД. Проверьте строку подключения." | Логирование, повтор подключения |
| Дублирование ключа | "Объект с таким наименованием уже существует." | Возврат фокуса на поле ввода |
| Пустое поле обязательного параметра | "Заполните поле 'Наименование'" | Подсветка поля, сообщение |
| Ошибка БД (ограничение) | "Невозможно удалить объект (на него есть ссылки)" | Информирование пользователя |

### 6.2 Логирование
- Логирование ошибок в файл: `Logs\ErrorLog.txt`
- Формат: `[2025-12-27 12:30:45] [ERROR] Описание ошибки`

## 7. ТРЕБОВАНИЯ К КОДУ

### 7.1 Стандарты кодирования

#### Именование переменных (CamelCase для C#)
```csharp
// Переменные
private string наименованиеОбъекта;  // camelCase
private int идентификатор;

// Константы
private const string СТРОКА_ПОДКЛЮЧЕНИЯ = "...";

// Методы

private bool ПроверитьПустоеПоле(string значение) { }

// Классы
public class ГлавнаяФорма { }
public class МенеджерОбъектов { }
```

#### Комментарии
```csharp
/// <summary>
/// Загружает все объекты из БД и отображает их в таблице.
/// </summary>
/// <returns>true если загрузка успешна, false иначе</returns>
public bool ЗагрузитьДанные()
{
    try
    {
        // Получаем данные из слоя доступа
        DataTable данные = доступКДанным.ПолучитьВсеОбъекты();

        // Привязываем к таблице
        сетка.DataSource = данные;

        return true;
    }
    catch (Exception исключение)
    {
        ОтобразитьОшибку("Ошибка загрузки данных: " + исключение.Message);
        return false;
    }
}
```

### 7.2 Безопасность
- **SQL-injection**: Использование ТОЛЬКО параметризованных запросов
```csharp
// Правильно:
using (SqlCommand команда = new SqlCommand("sp_Поиск_Объектов", соединение))
{
    команда.CommandType = CommandType.StoredProcedure;
    команда.Parameters.AddWithValue("@Наименование", значение);
}

// Неправильно:
string запрос = "SELECT * FROM Объекты WHERE Наименование = '" + значение + "'";
```

- **Закрытие ресурсов**: using() для соединений, команд, читателей
```csharp
using (SqlConnection соединение = new SqlConnection(строкаПодключения))
{
    soединение.Open();
    // ...
}
```

## 8. ТРЕБОВАНИЯ К ТЕСТИРОВАНИЮ

### 8.1 Сценарии тестирования
1. **Добавление записи**
   - Открыть форму добавления
   - Заполнить все обязательные поля на русском языке
   - Нажать "Сохранить"
   - Проверить: запись появилась в таблице, сообщение об успехе

2. **Редактирование записи**
   - Выбрать запись в таблице
   - Нажать "Изменить"
   - Изменить одно из полей
   - Нажать "Сохранить"
   - Проверить: изменение отражено в таблице

3. **Удаление записи**
   - Выбрать запись
   - Нажать "Удалить"
   - Подтвердить удаление
   - Проверить: запись удалена, сообщение об успехе

4. **Печать**
   - Нажать "Печать"
   - Выбрать принтер
   - Проверить: таблица выводится с правильным форматированием

5. **Обработка ошибок**
   - Отключить БД
   - Попытаться загрузить данные
   - Проверить: появилось корректное сообщение об ошибке

### 8.2 Результаты тестирования
Должны быть документированы результаты минимум двух сценариев с скриншотами.
